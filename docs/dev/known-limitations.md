# 已知限制与待打磨项

本文只记**已确认为真、但本阶段有意不修**的项。每条必须写清：现象、为什么不现在修、什么条件下该修。

**写入规则**：只在"能复现 / 有实测证据"时登记；猜测不进来。修掉后删条目并记到对应修订记录，不留在文里当历史。

## L1 设置页分组导航暴露为 `Toggle`，语义应为"选项卡"

**现象**：设置页三个分组（下载 / 网络 / 界面）在 UI Automation 树里是 `Button` + `Toggle=True`，屏幕阅读器念成"可切换按钮"，而不是"选项卡 1/3"。`Toggle` 也不传达"三选一互斥"。

**这是修复，不是退步**：改前用 `selectable_label`，**完全点不动**（无 `Invoke`、无 `SelectionItem`、无 `Toggle`，辅助技术与 UIA 脚本都无法驱动）。M3 的 R3 前置体检因它报过假红，修好后 PASS。

**能用性已证**：`Toggle` 可驱动、切换真的换组（下载组 8 个单选、网络组 0 个复选、界面组 12 个复选）、当前组有 `selected` 高亮。

**为什么不现在修**：要精确语义得让 egui 暴露 list/tab 角色，可能要把分组容器换成别的控件树；而当前形态是**真缺陷的修复**，先保"能点"。语义属打磨。

**该修的条件**：有屏幕阅读器用户反馈，或做无障碍专项。修时判据要一起改——`Toggle` 也可作为可接受形态之一，别把"非 TabItem 即失败"写成门禁。

## L2 面板内部行为日志尚未落盘（写入器已就绪，**转发未接**）

**现象**：需求 F11 要求 `ariahost.log` 按大小轮转 10MB×5 份，但直到 M3 之前**全仓没有写入点**——清理引擎在轮转一个永不存在的文件；面板日志只在内存环形缓冲，进程一退就全丢。

**后果**：用户报"点 X 卡住"→ 导诊断包 → 包里只有 `aria2.log`，面板自己走到哪一步一行都没有。

**当前进度**：写入器已落地（`common/src/logfile.rs`：`init/write/Level`，写盘前 `redact`、轮转复用 `rotated_index`、失败降级不 panic），`main.rs` 已按平面初始化，`service.log` 的 `Level` 已统一。**缺的只有面板侧的 1 行转发**——挂在 `LogBuffer::push`（`crates/ariahost-ui/src/logbuf.rs:29`，唯一收口点），接完后本条可删。

> 为什么不散着挂：`app.rs` 里 `self.log.push` 有几十处，逐个挂必漏，且以后新增的行会忘。

## L3 管理员上下文 `--quit` 未实测

**现象**：控制管道 DACL 已 allow `BA`（本机管理员），但**没有实测过**管理员身份下 `--quit` 能否连上并停下管理员启动的面板。

**为什么没测**：本机会话审批被禁、取不到提权令牌（UAC 必须人来点）。**不是设计问题，是取证边界。**

**已覆盖的风险**：非管理员路径已实测通过（`accepted` exit 0、面板 ≤15s 退出、无残留）。真正会崩的是"该连的连不上"，而这条已被覆盖；"不该连的能连"由 DACL deny 网络登录兜底（跨用户未验证，本机只有单一交互用户）。

**该修的条件**：有管理员用户报 `--quit` 失败，或做安全审计。手工验收项见 `.scratch/m3/manual-acceptance.md`。

## L4 egui 的 accesskit 只消费 `Click`：`SetValue` / `Toggle` / `SelectionItem` 显式驱动无效

**现象**（源码级已定位，`egui 0.37`）：

| 控件 | UIA 暴露 | 实际效果 |
|---|---|---|
| `Button`（含分组导航） | `Invoke` / `Toggle` | **可驱动** |
| `TextEdit` | `ValuePattern.SetValue` | **不生效**：provider 回声新值，但 app 状态未变（铁证：`保存` 一直 `disabled`——`is_dirty()` 若为真必变亮） |
| `RadioButton` | `SelectionItem.Select` | 空转（egui 不消费该动作） |
| `CheckBox` | `TogglePattern.Toggle` | 空转 |

根因：`egui-0.37.0/src/context.rs:1769` 只处理 `input.has_accesskit_action_request(id, Action::Click)`；`response.rs:1001/1004` 只注册 `Focus` 与 `Click`。`rich_text_editor/builder.rs:1128` 虽然 `add_action(Action::SetValue)`，但返回值没有被应用到文本状态。

**影响**：屏幕阅读器 / 语音输入 / 自动化脚本只能"发现并点击"，**不能"程序化设置值"**。对只用键盘的用户不构成阻断（Tab + 打字可用），但比鼠标用户多一道门槛。

**这直接影响我们的取证方式**：UIA 驱动不了改值类验收条目。已定的做法是在面板里加**隐藏自检驱动**（`--panel-selftest --drive …`：把合成事件灌进 `egui::RawInput` 跑真正的 `ui()`），**不碰 Win32 输入、不需要解锁、可在 CI 跑**。

**为什么不现在修**：这是 egui 上游行为，改它要 fork/补丁整条输入链路；且修好也没有用户可见收益（键盘用户不受阻）。

**该修的条件**：egui 上游支持；或有屏幕阅读器用户明确要求"用语音设置数值"。届时判据要一起改，别把"必须支持 `SetValue`"写成门禁。

## L5 上游 aria2 关闭本身需 ~4.1 秒（非本产品可控）

**现象**：发 `aria2.shutdown` 或 `forceShutdown` 之后，`aria2c.exe` 进程**自身**要 **4.1 秒**才退出（空载、无任务也一样）。

**影响**：面板"退出时停 aria2c"的最短耗时地板就是 ~5.1s（启动 0.73s + 停止 4.2s）；UI 必须给"停止中…"的等待态，不能假设秒退。

**为什么不修**：这是上游 aria2 的行为，不在我们代码里。我们能做的是**别在等待期冻帧**（M2-3 已用 100ms 自驱重绘修掉"点停止后画面冻结 30s"）。

**该修的条件**：aria2 上游改动；或我们改走 `TerminateProcess`（**不采用**——会留下半写文件与控制文件，比多等 4 秒坏得多）。

## L6 「在线下载核心」在受限网络下不可用（线路1 长期 404、线路2 依赖 GitHub 可达）

**现象**：首次运行引导卡的在线下载，在本机实测**四条线路全失败**：

| 线路 | 结果 | 根因 |
|---|---|---|
| 线路1（`https://r.alusss.cn/` 前缀代理） | `AH-E3003` | 该域名对**所有路径**返回 CF 前置 nginx 的 404 HTML（1253 字节）——2026-11-22 侦察期即实测，从未可用 |
| 线路2（直连 GitHub release） | `AH-E6001 timeout` | 本机到 `github.com` 超时（`api.github.com` 可通，`github.com` / `release-assets.githubusercontent.com` 不通，2026-11-25 多次复现） |

聚合后为 `AH-E6007 全部下载线路失败`。**诚实失败，无假装成功**（失败路径行为是正确的）。

**影响**：在目标网络里「装完 → 面板自己下核心」这条路走不通，等于开箱不可用。

**处置**：首版改为**安装包自带 aria2c**（`task-54`），在线下载降级为「升级 / 换版本 / 补充」通道。自带后首次运行不再需要网络。

**已知的可读性欠账**（非缺陷，下一批改）：失败时用户看到的是三条线路的**原始错误串**，应合成一句人话（「在线下载不可用：镜像不可达、GitHub 不可达」）+ 可展开详情。

**该修的条件**：有可用镜像（含正确校验与 Content-Type 预检）；或换掉线路1 的域名。

## L7 「取消」撞上真实失败时，报失败而不是「已取消」（**设计语义，勿当 bug**）

**现象**：点取消后，若当前步骤在收尾前就**真的失败**了（例如取消恰好落在一次网络请求超时上），本次引导的结论是 `Failed(<原始错误>)`，而不是 `Cancelled`。

**为什么这样定**：`Cancelled` 的意思是「用户主动放弃，结果未知也不需要知道」。而这里我们**确知失败了**——把已知的失败抹成「你取消了」会丢掉信息，用户下次重试时也无从判断是网络问题还是自己点错了。

**判据**：取消是**请求**，不是**结论**。措辞上「已请求取消，当前步骤完成后停止」是准确描述（`task-52` 实测文案即如此）。

**该修的条件**：不修。若将来用户反馈困惑，改文案（「已取消（期间发生过一次网络失败）」），不改语义。

## L8 无交互桌面下「取消授权」与「弹不出授权框」不可区分（`ShellExecuteExW(runas)` 阻塞 122s 后返回 1223）

**实测（2026-11-25，锁屏/无交互桌面，v0.1.1 产物）**：面板点「安装为服务」→ `ShellExecuteExW(…, "runas", …)` **阻塞 122.29 秒**，随后返回 `LastError = 1223`（`ERROR_CANCELLED`，即「操作已被用户取消」）。

**同一条件下另一次实测（同日、另一会话、同一产物族）**：**300 秒内不返回**，既没有 `1223`、也没有任何结论 —— 说明「不返回」也是可能结局，而且时长不可预测（122s / ≥300s / 正常桌面上的秒级返回）。因此**不能**把某个固定秒数当成「用户拒绝」的判据。

**还有第三次观测**：`0.8s` 立即返回 `1223`。但那一轮的启动对象在被测工作区路径下，与「沙箱拦截从受管工作区发起的 ShellExecute」（见 `test.md` 6.7，同样返回 1223）混淆，**不能单独作为 UAC 行为的证据**。三次观测合起来只支持一个结论：**返回码与耗时都不可作为「用户是否拒绝」的判据**。

**含义一（架构约束）**：提权**必须**在后台线程执行。UI 线程同步调用 = 点一下假死两分钟；等待期间必须持续出帧并显示「已等 X.X 秒」。

**含义二（文案约束，重要）**：`1223` **同时**覆盖「用户点了取消」和「当前会话根本显示不出授权框（锁屏、无交互桌面、服务会话）」两种情况。因此：

- 文案**不许**断言「你拒绝了授权」；
- 正确写法：「已取消提权授权」+ 等待 ≥60s 时补一句「也可能是当前会话无法显示授权框（锁屏/远程/服务会话）」；
- 只出**信息条（灰）**，不出错误条（红）——它不是一个错误。

**影响范围**：面板「安装/卸载服务」、安装器的「同时注册为服务」勾选项。后者在无人值守安装（`/S`）里应当**默认不勾选**，否则会静默等两分钟。

**为什么不修**：这是 Windows 的返回值语义，不是我们的选择。我们能做的只有「不阻塞 UI」+「文案不冤枉用户」。

**该修的条件**：Windows 提供区分两者的 API；或我们改走服务助手（安装器 `runas` + 显式状态机，届时「取消」由我们自己的退出码表达）。

## L9 `--backend dx12` 私用工作集 116.4 MB，破 100 MB 闸门（EG-4）

**现象**：同一产物、K32 句柄口径、30 采样 / 60 s、单实例——显式 `--backend dx12` 的 PWS 是
**116.4 MB（116.3–116.6）**，超闸门 16 MB；同期 `--backend vulkan` 是 **51.6 MB**，`auto`（全集枚举）是 **72.0 MB**。

**已做的**：`auto` 收窄为串行探测、只开一个后端，且顺序是 **Vulkan → DX12 → GL**（内存优先），所以
**产品主路径不再走这条路**——本机 `auto` 落在 Vulkan，72.0 MB，余量 28 MB。DX12 只在 Vulkan 不可用时兜底。

**没做的**：没把 DX12 从枚举里删掉，也没能把 DX12 的内存压下来。差距（相对 Vulkan +65 MB）未逐项归因，
嫌疑是驱动侧工作集与交换链，需要 ETW / 供应商工具才能拆，不在本批预算内。

**该修的条件**：出现「只有 D3D12 可用」的真实机型（例如某些远程桌面 / 老 Intel 驱动），或产品决定
放弃 DX12 兜底。届时的选项：①继续查 DX12 内存；②接受该机型超闸门并在设置页如实标注；③把 D3D11/GL 做成兜底。

**复现**：`.scratch/m3/acceptance/` 下的三后端测量脚本，判 INCONCLUSIVE 的条件是采样<20 / 句柄取数失败>0 / 采样期实例数≠1 / 进程提前退出。
