## 1. 需求概述

为 Windows 提供一个 aria2 服务管理器（产品名 AriaHost，仓库代号 wasm）：把 aria2 下载核心以「可选服务化 + 面板 + 网页管理页」三种形态交付给用户，覆盖安装、核心获取、日常下载管理、磁盘治理、版本升级全生命周期。产品定位是**轻量中文桌面工具**，不是 aria2 的全功能前端：界面只暴露精选配置，不裸露 aria2 全部选项（见 research-cache-ux.md §11 对 Motrix/AriaNg 的反例分析）。

仓库当前无业务代码（无 `Cargo.toml`），处于设计定版阶段；执行层文档与工作流已落盘但未运行（见文首现状）。

## 2. 背景与现状

- aria2 是命令行下载器，官方仅发布 zip 资产（1.37.0：win-64bit 2,475,379B / win-32bit 2,558,495B，2023-11-15 发布，见 research-version.md §2），无官方 GUI、无官方校验和（资产 digest 全 null，见 research-version.md §4）、无 Windows 服务化能力（`--daemon` 在 Windows 构建静默空操作，无 StartServiceCtrlDispatcher，见 research-service.md §3）。
- 现有第三方方案各有缺口：AriaNg 是纯 Web 前端（secret 明文输入、无托管）；Motrix 把 aria2 封装成 Electron 应用（重）；NSSM/WinSW 通用服务包装器无 RPC 感知、无优雅停止语义（见 research-service.md §3）。
- 用户指定代理线路 r.alusss.cn 于 2026-11-22 实测**整体不可用**（根路径与全部拼接变体均返回 CF 前置 nginx 404 HTML 1253B、20s 超时、TLS 断连），GitHub 直连实测可用（302→206、支持 Range 断点续传）（见 research-installer.md §3）→ 默认线路改直连（Q2）。
- Rust 工具链现状：Rust 1.100 起 i686 Windows 目标降为 Tier 1 without host tools（std 预编译继续、需 x64 宿主交叉编译）（见 research-gui.md §7）；egui 0.37 整条栈要求 Rust ≥1.95（见 research-egui.md EG-1，工具链 pin 属 M1 悬置项 S2）。
- 装机完整性现状：Rust MSVC 目标默认动态链接 CRT，依赖非系统自带的 `VCRUNTIME140.dll`；当前 CI 产物只上传单个 exe、安装包不含运行库 → 干净系统/Server Core 有「双击即失败」风险（架构文档 §4.13，D13）。

## 3. 用户角色与场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 普通用户（Win10/11） | 日常：装好后常驻托盘，丢链接就下 | 中文、免打扰、退出不中断下载（S1） |
| 重度下载用户 | 大文件、批量任务、限速与分片调优 | 网页页完整管理、第三方客户端接入（S2） |
| 服务器管理员（Windows Server） | 无人值守下载服务；Server Core 无桌面 | 服务模式手动触发、RPC lan 档、headless 与网页页可用、无需桌面会话（S3） |
| 离线/受限网络用户 | 首装无网或 GitHub 不可达 | 本地 aria2 兜底、镜像模板可配置（S4） |
| 开发者/维护者（新增） | 改代码、出安装包、排查问题 | 一条命令构建、CI 出包可下载、文档能照做（S5） |

### 3.1 三形态职责边界（第 9 条拍板的落地）

| 形态 | 负责什么 | 不负责什么 |
|---|---|---|
| 面板（托盘常驻，egui 自绘） | 活动任务速览与启停/暂停/删除、一键打开下载管理、磁盘治理提示、RPC/服务/版本/通知设置入口 | 批量编辑、aria2 高级选项编辑、跨浏览器使用 |
| 网页管理页（`http://127.0.0.1:<web.port>`，默认 6875） | 完整任务管理（添加/编辑/批量/高级选项）、任务历史检索 | 托盘交互、服务/安装器/磁盘治理设置面 |
| 第三方客户端（RPC `localhost:6800`） | 用户自带工具全功能调 aria2（AriaNg/Motrix 等） | AriaHost 不提供其 UI，也不校验其行为 |

- 网页页由「当前托管 aria2 的进程」提供（服务模式=ServiceHost；headless=GUI 进程），secret 不出后端（见 F3/F5）。
- 面板与网页页是**两套 UI、一份 HTTP/JSON 契约**（架构文档 §4.4）；不再有「同构复用」假设。
- 「一键打开」的语义 = 打开**自托管网页页**（非裸 6800 RPC），URL 由 `web.port` 渲染（不是硬编码 6875），降级链见 F3；托盘菜单「打开下载管理」在 aria2 不可用时仍恒可点（转引导）。

## 4. 功能性需求

编号 F1–F12；每条按「输入 → 处理 → 输出」压缩表述。默认值与键名以架构文档 §4.11 为准（**定版 52 键逐键清单见 §4.11.1**），两文数字一致。

### F1 安装与分发
自写 NSIS 安装器（`installer/ariahost.nsi`，437 行，已交付未编译【未验证】）：**首版只发布 per-user 单包**，全程免 UAC，**默认**装到 `%LOCALAPPDATA%\Programs\AriaHost`（安装向导目录页可改）；全机变体（`makensis /DPER_MACHINE`）为同源编译变体，M4 才进发布矩阵。组件：主程序（必需）、开始菜单快捷方式（写 AUMID，R9）、桌面快捷方式（可选）。**服务组件只在全机变体显示**；per-user 包内该组件被隐藏（不留「勾了也失败」的项），用户装后从设置页「一键装服务」走一次 UAC（F4/R9）。**安装包只含 `ariahost.exe` + `uninst.exe` + 快捷方式/注册表**：不带 DLL、不带 VC++ 运行库（D13 静态 CRT）、默认不带 aria2c、不带配置。卸载：先 `--uninstall-service`（可拒绝则保留服务并提示），配置与版本库问询删除，下载目录永不自动删；服务平面 `%ProgramData%\AriaHost\` 需管理员权限，卸载器不静默删、只提示复用或手工命令。输入：用户选择 → 输出：可启动面板 + 可选已注册服务。（见架构文档 §4.10/R9）

### F2 aria2 核心获取
输入：首次运行引导（MSG-U06）或设置页「重新获取核心」→ 处理：在线下载走「镜像模板→直连→本地文件→跳过」回退链，每线路预检（首字节验 Content-Type/Content-Length/zip 魔数），sha256 构建期自算必校验 → 输出：受管版本库落位（per-user：`%LOCALAPPDATA%\AriaHost\cache\aria2\versions\<ver>\`；服务平面：`%ProgramData%\AriaHost\aria2\versions\<ver>\`，R9-b；两平面同步规则见架构 R11），失败可见错误码绝不静默降级。（见 research-installer.md §3、research-version.md §6）
**v2.0 变更**：安装器内不再有「aria2 来源页」——来源选择统一在首次运行引导 + 设置页；安装器只保留「同目录自带 `aria2c.exe` 则一并安装」。理由见架构文档 §4.10（把回退链搬进 NSIS = 无单测脚本重写升级器）。

### F3 任务管理与三形态入口
- 面板内嵌任务列表：活动/等待/完成分组、速度、进度（0.5–1s 刷新【估算】）、暂停/继续/删除；>200 行必须虚拟滚动（架构文档 §4.2.2 前提③）。
- 网页管理页：浏览器打开 `http://127.0.0.1:<web.port>`（默认 6875），完整任务管理（添加/编辑/批量/高级选项），零构建前端由服务端内嵌托管（架构文档 §4.4）。
- 一键打开：面板顶部按钮+托盘菜单+`Ctrl+Shift+M` 三入口；服务未运行走「启动并打开」降级链（MSG-U05）；aria2 缺失转首次引导（MSG-U06）。（见 research-cache-ux.md §9.2）
- 单实例（**只对面板形态**，v2.1 写死优先级）：**先解析 argv，再决定是否进入 GUI/单实例逻辑**；`--service`/`--install-service`/`--uninstall-service`/`--write-aumid`/`--quit` 是短命助手或独立进程形态，**不激活窗口、不转发命令行、不参与 GUI mutex**；只有无参（面板）模式参与 `CreateMutexW` 互斥，第二个面板实例激活已有窗口并退出（`AH-E9001`，架构文档 §4.1.1/§4.1.4）。
- 第三方客户端：RPC `localhost:6800` 直连（secret 设置页可查看复制）。
- 三形态各自有验收：面板=#16、网页页=#17、第三方 RPC=#18（v2.1 新增，见 §6）。

### F4 服务托管三模式
`service.mode`：`windows-service`（SCM 托管）/`headless`（面板进程直接拉起）/`off`（不托管）。服务 `start_type=manual`（SCM demand：系统开机不自动拉起，面板操作时按需启动）为默认。停止链固定 saveSession→shutdown→15s→forceShutdown→10s→强杀（ST-06 的 ≤5s 计入 ST-05 第一段，总上限见 N4）。模式切换必经完整停止链且 6800 端口独占（不可双开）。（见 research-service.md §5–§6）
**面板一键注册/卸载服务（执行口径 = R9）**：入口=设置页「服务」区+状态栏服务态按钮；前置=一次 UAC（`ShellExecuteExW runas` 拉起 `ariahost.exe --install-service`）；助手按序完成 ProgramData 目录与 ACL、服务平面版本库与 machine-scope secret 准备、`CreateServiceW("AriaHost", LocalSystem, demand)`；成功判据=`QueryServiceStatus` 且 `service.mode` 已切 `windows-service`（≤30s）；失败态=取消 UAC（`ERROR_CANCELLED`=1223）→不改任何配置、不落半状态、提示「已取消」（`AH-E5002`）；助手任一步失败→回滚并报 `AH-E5003`。per-user 安装**不允许**直接 `sc create`（必然拒绝访问，架构文档 §7.1）。
**并发前提（v2.1 补）**：面板运行中点「一键装服务」时，提权助手是第二个 `ariahost.exe`——必须按 F3 的 argv 优先规则豁免于单实例检查，否则助手会被当成第二实例激活面板后退出，UAC 路径静默失败（验收 #3b 含此用例）。

### F5 RPC 接入与安全
默认 `localhost` + 自动生成 32 位 secret（DPAPI 存储；headless=user scope；服务模式=machine scope + `CRYPTPROTECT_LOCAL_SYSTEM`，**只有 ServiceHost 解密**，面板经命名管道（DACL 限当前用户）向 ServiceHost 索取，不直接读 DPAPI blob；威胁模型见架构文档 §4.6.1）；`lan` 档默认关，开启需 MSG-U08 二次确认+防火墙预建；`off` 档关闭 RPC。网页页经同源反代调 RPC，secret 不落浏览器。（见 research-service.md §9、research-cache-ux.md §9.4）

### F6 磁盘占用治理
先检测（启动延迟 60s + 每 24h 定时）→ 再提示（<50MB 不打扰；50–500MB 托盘气泡一次/日；≥500MB 或下载盘 <5GB 弹提示卡）→ 一键清理（明细勾选+可取消+回执）。孤儿 `.aria2` 7 天阈值；硬边界：绝不自动删已完成文件/活动任务/配置/session/secret/激活版核心。（见 research-cache-ux.md §4）

### F7 启动/退出行为
启动：session 检出未完成任务 → MSG-U03（继续全部/暂停等待/放弃+可记住）；启动默认最小化到托盘（`ui.start_minimized=true`），但**先弹 MSG-U03 再最小化**。退出：真退出且有活动任务 → MSG-U04（托盘继续/暂停退/停止退）；点 X 默认 `tray` 不询问。所有退出路径必经 ST-06→ST-05 收尾；ST-06 最多 5s 且与 ST-05 第一段并行计时（**总上限 25s，不是 30s**，v2.1 明确）。（见 research-cache-ux.md §8–§9.1）
**saveSession 兼容**：`aria2.saveSession` 在最低支持版本 1.19.1 上可用性未知（引入版本未定位）→ 启动时探测能力（`getVersion`+`listMethods`），不支持则退化为 `--auto-save-interval` 定时落盘 + `shutdown` 前等待一个保存周期，面板信息条明示（这是 N6 最低版本承诺的代价，见架构文档 §5）。

### F8 aria2 版本管理
检查更新四态文案绝不合并：无更新（**常态**：1.37.0 自 2023-11-15 即最新，上游发布极慢，文案须解释这一节奏）/网络故障/代理返回非 JSON/429 限流。版本选择：在线窗口 24 版（1.19.1→1.37.0）+本地 manifest 离线列表。升级 8 步状态机，切换前旧版照常服务，失败自动回滚上一版。（见 research-version.md §5、§7）**跨平面**：服务模式与 headless 各持一份版本库，激活指针按 R11 同步/比对，不允许出现「面板显示已升级、服务模式仍跑旧核心」的静默分叉。

### F9 统一异常处理
六分类（用户可修复/环境缺失/网络/权限/aria2 内部/未知）+文案模板（发生了什么/影响/建议动作）+错误码 **`AH-E####`**（v2.0 前缀定版，R10；段位见架构文档 §4.12）+可执行动作注册表。禁止把 aria2 stderr 裸弹给用户。（见 research-cache-ux.md §6）

### F10 界面、托盘与通知
中文界面（首版单语）；主题跟随系统；egui 自绘面板（无原生控件观感，需自定 theme）；托盘左键面板、右键菜单最小集（打开下载管理恒可用）；开机自启 HKCU Run 免提权；DPI 125%/150%/200% 与多屏钳制（架构文档 §4.2.4）。（见 research-cache-ux.md §8.3–§8.4、§9.3）
**IME 纪律（硬约束，非「能力具备」）**：禁止每帧 `request_focus`（含包装组件/`request_focus_next_frame` 的每帧调用）——egui `Memory::request_focus` 无条件 `interrupt_ime()`（Issue #8813，修复 PR 未合并），违反即中文完全无法输入；只在焦点状态变化时调用一次或自维护焦点 id。验收 #13 为 M2 门禁（架构文档 §4.1.3）。
**通知**：完成/失败通知按 R9 降级链 `Toast → 托盘气泡 → 面板内条幅 → 提示音`，任何一级失败不得静默丢弃；`notify.backend` 可强制指定。

### F11 日志与诊断

### F12 CI 与发布流水线（v2.0 新增，用户第 10 条）

### 7.1 命名评估（第 3 条原话 → Q7，已定 B）

背景：用户原话提出「软件英文名 wasm 是否合适」。定版前改名成本≈0（只改文档与脚手架）；发布后改=全链迁移负担。

**问题实质（三个独立层面）**：
1. **检索冲突**：`wasm` 是 WebAssembly 的通用缩写——搜索引擎前几页全被运行时/规范/工具链占据，产品名检索可发现性差、误搜率高（通用知识，非侦察实测）。
2. **认知混淆**：进程 `wasm.exe`、服务目录、`%LOCALAPPDATA%\wasm` 与「WebAssembly 工具」语义撞车；杀软生态无既有信誉可继承，误报申诉从零起步（与 SmartScreen 风险叠加）。
3. **零产品语义**：`wasm` 不含 aria2/下载/宿主任何线索，新用户望名不知用途。

**三候选对比（结论：B）**：

| 候选 | 优点 | 代价 | 结论 |
|---|---|---|---|
| A. 保留 `wasm` | 零改名成本；仓库名不动 | 检索冲突+认知混淆长期存在 | 否 |
| B. **AriaHost** | aria 生态检索亲和；「宿主」语义直指产品本质（托管 aria2） | 全链改名一次；M0 窗口内成本≈0 | **采纳** |
| C. AriaDock | 同 B 检索优势 | 「停靠」语义偏容器场景，与「服务宿主」定位略偏 | 否 |

**改名成本链**（M0 后逐级放大，已在本版一次性完成）：进程名 → 服务名（`AriaHost`）→ 安装/配置/运行时目录 → 注册表与自启键 → 快捷方式/开始菜单 → 安装包名（`AriaHost-<ver>-x64-setup.exe`）→ 错误码前缀（`AH-`，R10）→ README/文档/发布页。落地总表见架构文档 §3.3。
